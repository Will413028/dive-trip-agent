# 目前功能現況

更新：2026-10-01。依據目前產品程式與 [release evidence](release-evidence.md)，不是新 roadmap。

**目前可以在本機操作完整的離線 DEMO 行程工作台；真模型品質尚未通過，服務尚未公開部署。** 一般工作台使用固定情境，不代表可以理解任意自然語言。

## 已實作、可在本機操作

| 功能 | 現在可以做什麼 | 使用邊界 |
| --- | --- | --- |
| 建立示範行程 | 從首頁進入一般規劃、預算衝突情境 | 主要使用合成 DEMO 資料 |
| 需求編輯 | 編輯目的地、人數、潛水／非潛水分配、日期／天數、預算、住宿偏好與步調，產生修改提案 | 小琉球、綠島、墾丁；一趟一個目的地，1–6 人、2–7 天、TWD |
| 目的地資訊 | 查看精選目的地與目錄資料 | 有限目錄，沒有即時全網搜尋 |
| 每日行程卡片 | 新增活動、移動日期／時段、替換目錄項目、移除活動、修改房數 | 透過提案操作，確認前不保存修改；沒有拖曳排序 |
| 鎖定／解鎖 | 保護已選項目的內容、日期與費用依據 | 修改鎖定項目前須先解鎖並接受提案 |
| 差異提案與確認 | 查看增刪改、費用差異、衝突與待確認項目；接受或拒絕 | 舊版本提案不能直接套用；拒絕不改行程 |
| 預算試算 | 程式計算每人、房晚與固定費用，顯示已知小計、未知項目與排除費用 | 未知價格不當零；DEMO 價格不當真實報價，不保證符合預算 |
| 對話互動 | 顯示工具進度、結構化回答與確認流程 | 離線固定情境，例如「第二天下午留白」「試算目前預算」「把行程改為悠閒」「人數未定」「查詢目的地」 |
| 版本保存與復原 | 保存完整行程版本；指定舊版內容復原成新版本 | 保留歷史，重送同一請求不重複建立版本 |
| 刷新接續 | 讀回已保存行程、回答與等待確認狀態 | 中斷或失敗顯示真實狀態，不自動重送未知模型請求 |
| 地圖 | 查看具有已核對座標的項目，點擊後載入 OpenStreetMap 底圖 | 缺座標顯示待確認；沒有路線規劃或交通時間推估 |
| 桌面／手機介面 | 桌面並列對話與工作台；手機切換對話、需求與行程區域 | CI 驗證瀏覽器與手機 viewport，不等同實體手機驗收 |
| 固定快照分享 | 預覽公開欄位、建立唯讀分享連結、撤銷連結 | 排除私人對話等欄位；編輯原行程不更新分享；本機連結不是公開服務 |
| 刪除行程 | 確認後立即封鎖行程與分享，顯示刪除中；完成清除後顯示已刪除 | 持久工作可追蹤狀態；quota 與受保護評估證據依留存規則保留 |
| 匿名使用 | 不註冊即可使用，由服務端 session 控制行程讀寫 | 預設期限 30 天；不承諾跨裝置恢復 |
| 展示頁面 | 首頁示範入口、靜態查詢失敗示範與 `/case-study` 案例頁 | 靜態失敗畫面不代表一次實際 live 執行 |

## 已有技術實作，尚不能當成完成的產品能力

| 項目 | 現況 |
| --- | --- |
| 真模型規劃 | Python runtime 已接受控模型／工具流程，但新版品質驗收未通過；一般工作台不開放真模型入口 |
| 回答可信邊界 | strict AnswerPlan、當回合 evidence 引用及服務端計算／呈現已實作；能攔截不合契約的輸出，不代表模型能完成任務 |
| Provider 與用量控制 | 已有 adapter、quota、模型／工具上限、未知用量保守結算與停止政策；真模型只經另行授權的隔離入口 |
| 持久執行 | Temporal 管執行與等待，PostgreSQL 管行程、版本、回答與帳務；確認後直接產生 receipt，不再呼模型 |
| 到期／清理 | 已有到期拒讀與本機 worker 清理；正式託管排程、監控與告警尚未配置 |

## 尚未完成

- **真模型品質驗收**：30 案尚未通過。最後 probe-8 完成一次預算工具後回傳 TEXT、無工具呼叫，按契約停止，沒有行程變更。已修正 prompt，明確要求透過 `final_answer` tool call 收尾；修正的真模型效果尚未驗證。
- **正式公開服務**：沒有 public deployment；正式 ingress、proxy/IP 信任、secret 設定、運維預算、排程／告警、備份還原與 kill-switch／rollback 尚需驗收。
- **真模型展示**：尚未完成可對外聲稱通過品質驗收的 live 展示與發布驗收。
- **資料有效性**：主要為 DEMO；少量景點名稱／座標已人工核對，價格、開放與可訂狀態仍待確認。
- **CI Actions runtime 維護**：已有盤點，升級與驗證尚未完成。

剩餘工作的排序維持在 [release evidence「執行交接」](release-evidence.md#執行交接)，執行細節在 [release completion plan](release-completion-plan.md)。
