# 潛旅筆記：本機 demo 腳本

這份腳本配合 `/case-study` 個人作品案例頁。首頁已提供一般規劃、鎖定住宿的預算衝突，以及明示的查詢失敗靜態劇本；不把靜態文字當成真模型故障。公開部署與完整live評估通過仍是發布門檻。

2026-09-27新版切換：僅使用獨立離線demo；舊live及以下舊錄影／評估證據保留歷史，不代表新版通過。核心回答改為受控AcceptedAnswer，金額統一顯示`TWD 4300.00`等兩位小數格式（下表NT$數字為相同數值）。待確認回答必須先有已保存提案；確認後顯示已套用／拒絕的明確receipt。當前驗收進度以[重構計畫](superpowers/plans/2026-09-27-grounded-answer-refactor.md)為準。

## 展示前提

- 使用操作者已準備好的本機 fixture 工作台，從 `/case-study` 的「前往互動 demo」連至 `/`，點「試玩一般規劃」建立獨立示範行程。啟動需求見 [README](../README.md)，此腳本不要求啟停 DB、build、讀取 secrets 或啟用真模型。
- 對話面板須顯示「固定模型 DEMO · 非真實 LLM」。一般啟動不呼叫 Gemini；固定回覆不能示範任意自然語言能力。若模式不同，先停止此劇本，不把 live 操作當成 fixture。
- 技術為 Next.js、TypeScript、PostgreSQL、Google ADK TypeScript＋AG-UI；已有 provider adapter，但本次 live 入口停用、只展示離線流程。不要把首頁既有「未接 LLM」文案讀成整個專案的現況；以對話面板模式標籤及 [model adapter](model-adapter.md) 為準。
- 只用合成需求，不輸入個資、客戶秘密或真實訂單。錄影只取應用畫面，不展示環境檔、終端憑證、私人對話或完整分享 token。`tests/e2e/release.spec.ts`另提供可重現的fixture錄影流程，停在分享預覽以免錄入token；是否實跑通過見release evidence。
- 桌面直接操作對應面板；390px 手機以「需求／對話／行程」切換。錄製主流程約 4–5 分鐘，等待完成後再繼續，不以時間壓力跳過確認。

## 主流程：一般規劃 → 鎖定 → 局部調整 → 差異 → 復原 → 分享

| 段落 | 操作 | 畫面證據與旁白 |
| --- | --- | --- |
| 0:00 個人作品 | 從案例頁進入首頁，點「試玩一般規劃」。 | 「我負責需求、工作台、規則、版本交易與 Agent 整合。這是本機個人作品，未公開部署。」新行程為版本 1、小琉球 2 人／4 天／1 人潛水，示範已知費用 NT$4,300。 |
| 0:40 保留住宿 | 在行程點「鎖定 stay」，檢視差異，再按「接受修改」。 | 接受前維持版本 1；接受後為版本 2，住宿標示「已鎖定」。說明鎖定也經過提案確認。 |
| 1:15 局部調整 | 切至對話，輸入「第二天下午留白」，按「送出訊息」。 | 顯示固定模型模式與待確認差異：移除 `transfer`，住宿及早上 `tour` 保留；已知費用由 NT$4,300 變 NT$4,000，尚未套用、仍為版本 2。 |
| 1:50 確認與保存 | 待確認時刷新，回對話檢視同一提案，按「接受修改」；完成後再刷新。 | 版本 3、第二天下午活動已移除、住宿仍鎖定。「ADK 接續確認；產品交易保存完整版本。刷新不是重新生成行程。」 |
| 2:40 復原 | 切至行程，在「復原目標版本」填 `2`，按「復原此版本」。 | 版本 4 恢復接送及 NT$4,300，住宿仍鎖定。「舊內容存成新版，並未抹除歷史。」 |
| 3:10 分享 | 按「預覽分享內容」，檢視公開欄位，再按「確認公開並建立連結」。於同一台電腦開啟唯讀分享。 | 分享固定版本 4，不公開對話、日期或住宿偏好。連結持有者可讀；本機連結不是公開上線服務，不外傳。 |
| 3:45 固定快照與撤銷 | 回原工作台移除 `transfer` 並接受，得到版本 5；刷新分享頁，再回工作台「撤銷分享連結」，刷新分享頁。 | 分享仍是版本 4／NT$4,300；撤銷後不可讀。不要把建立分享說成發布整個服務。 |
| 4:30 收尾 | 回到 `/case-study`。 | 「模型提案、程式驗證、人來確認。這裡呈現可持久化的操作流程；Gemini smoke 不等於完整模型評估或正式發布。」 |

每次重錄從首頁建立新的示範行程，勿清除 DB 或重設他人的資料。版本數以新行程、依表操作且沒有額外修改為前提；數字不符先檢查操作歷史，不冒稱符合預期。

## 可選片段：現有 UI 能示範的邊界

- **容量衝突：**另開一份一般規劃，鎖定 `stay` 並接受；在「需求」將「旅客人數」改為 `4`，按「產生需求提案」。展示 `CAPACITY` 與停用的「接受修改」，拒絕後保留原版本。另有首頁「試玩預算衝突」一鍵入口，可展示預算降至TWD2,500的提案被拒絕且住宿保持鎖定。
- **未知費用：**另開一般規劃，展開 `tour` 詳細資料，將替換項目選為「示範潛水活動」，提出替換並接受。展示未知費用與「尚不能確認全程在預算內」；未知不是零，也不是免費潛水。
- **拒絕：**在新的未鎖定一般行程送出「第二天下午留白」，選「拒絕修改」。版本不增加，原接送仍在。
- **位置與失敗：**原 DEMO 沒有座標，會顯示「位置待確認」。本腳本不載入外部地圖；不以此冒稱查詢逾時或真模型故障已驗證。首頁lookup-failure是靜態fixture說明，不會讓正式Agent故障。

## 證據與措辭

資料以合成內容為主：10 筆 DEMO 外，僅花瓶岩、綠島燈塔、鵝鑾鼻燈塔 3 筆參考核對名稱與座標；價格、開放、入口及可訂狀態不在查核範圍。見 [資料依據](data-sources.md) 與 [素材授權](assets-license.md)。不提供預訂或潛水安全背書。

以下為重構前歷史驗證結果：395 unit、213 integration 通過（另有 2 個 live tests 預設 skip）；production E2E 為 55 通過、1 個手機重複錄影案例 skip。當時build、strict tsc、lint均通過；不是新版驗收數。完整驗證紀錄見 [release evidence](release-evidence.md)。

Fixture 錄影可由 `tests/e2e/release.spec.ts` 重現，原始影片留在 ignored local artifacts，不作 public download link。錄影範圍為鎖定、對話要求第二天下午留白、確認、復原及分享預覽，未涵蓋建立分享連結或撤銷；不得冒充真模型或完整發布驗收。

[模型契約](model-adapter.md) 說明 provider 與確認流程；新版真模型品質尚未通過，最新結果以 [release evidence](release-evidence.md) 為準。原始 report／claims／usage 留於 ignored local storage。公開的去識別化 10 情境 × 3 輪 domain fixture 不呼叫 Agent／LLM，不代表模型成功率、回應延遲或 live gate 通過，也不能用來重設 quota；詳見 [evaluation](evaluation.md)。

`tests/e2e/case-study.spec.ts`檢查案例頁聲明、demo導航、鍵盤入口與水平溢出；`release.spec.ts`檢查新入口與錄影流程，沿用desktop／390px mobile設定。runner使用隔離測試DB；案例頁測試不能取代真模型評估或公開部署驗收。實跑結果統一記在 [release evidence](release-evidence.md)。
